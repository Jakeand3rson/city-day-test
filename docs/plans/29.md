## Approach

Branch fix/29-last-entry-buffer. All changes are in index.html (about 90 lines added, 15 removed) plus new checks in qa-verify.mjs. I built a throwaway prototype of exactly this plan in the scratchpad: the patch is s2/patch29.py, the result is s2/proto29/index.html (diff in s2/proto29.diff) and the checks are s2/proto29/new29.mjs. It passes all 107 existing checks plus the 8 new ones. I also broke it on purpose six ways: WALK set to 0, the held rule removed, "Too late now" removed, dinner lateness turned off, the close time in the copy shifted, and the old Plan B filter put back. Each one makes at least one new check fail.

DECISIONS
- Arrival means now plus a 15-minute walk (WALK = 0.25). There's no travel model and no coordinates. The day lives in one walkable pocket, and stop-to-stop walks or short rides (Kenwood, Warehouse Arts, Midtown) run about 10–20 minutes. The ticket's numbers (60/45/20) are time to enjoy the place, so they have to be measured from when people get there, not from the tap. With arrival = now, coffee would get looser than today: it would stay on offer until 20 minutes before close, where today it's 30. With the walk, coffee stops being offered 35 minutes before close, sit-down food 60, museums 75.
- Default for types the ticket doesn't name (parks, shops, galleries, free dated events, the market, the brewery): a 30-minute visit. That keeps today's 30-minute number but now counts it from arrival. A stroll or a browse fits in 30 minutes, and arriving 15 minutes before a bookstore closes doesn't. This makes these places drop 15 minutes earlier than today.
- When a place posts a last entry, that's the cutoff. The type buffer applies only when nothing is posted, as the Proposal says. This is PM question 1, not blocking: it's a one-line switch in cutoffAt.
- "Go soon" shows in the last 30 minutes a place is still offered (TIGHT = 0.5).
- The dinner the engine picked follows the food rule on its closing side only. It stays revealable all afternoon even before it opens, because the strip already says "Dinner around 6". A creator's own booking is never cut off, since we don't know its hours.

DATA / CLASSIFICATION (next to stopView, ~1574)
  var STAY_MIN = { museum: 60, meal: 45, treat: 20, other: 30 };
  function stayFor(s): returns s.stay if the place set one. Otherwise: coffee, dessert or snack → treat; any other meal (lunch/dinner) → meal; cost "ticket" or "small" or a "museum" tag → museum (Sunken Gardens, FloridaRAMA, TBW, History, James, Woodson, Chihuly, MFA, Dalí, the glass studio, Shuffleboard, Good Folk Fest); everything else → other. Divide by 60 to get hours.
  function lastEntryOn(s, d, iso): takes s.lastEntry (a number, or a weekday map keyed "0"–"6" like `week`). It returns the hour only when it's below that day's close (s.end(d, iso)). Otherwise it returns null, so a special early-close day falls back to the type buffer.
  stopView gains two fields: last: lastEntryOn(s, d, iso) and stay: stayFor(s).

CLOCK (after isPlanDay ~603, and replacing openNow ~1931)
  function planHour() { return isPlanDay() ? nowNY().hour : null; }  // #30 extends only this
  var WALK = 0.25, TIGHT = 0.5;
  function cutoffAt(v, h) { if (v.gap && h < v.gap[0]) return v.gap[0] - v.stay; return v.last != null ? v.last : v.end - v.stay; }
  function openNow(v, how) {            // how: "inside" = open right now (Plan B); "held" = already revealed
    var h = planHour(); if (h === null) return true;
    var at = h + WALK;
    if (v.gap && h < v.gap[1] && (how === "held" ? h >= v.gap[0] : at > v.gap[0] - v.stay)) return !how && h + 1 >= v.gap[1];
    if (how === "held") return h < v.end;
    return v.start <= (how === "inside" ? h : h + 1) && at <= cutoffAt(v, h);
  }
  function closingLine(v): returns "" off the plan day, when the view has no stay (a custom anchor), or once the current stretch has closed. The current stretch ends at the midday break (gap[0]) if that's still ahead, otherwise at v.end. The label is "Last entry <t>" when a last entry is posted and no break is ahead, otherwise "Closes at <t>", always using fmtHour of the posted time. If h + WALK > cutoff, the line is "<label>. Too late now.". If h + WALK > cutoff − TIGHT, it's "<label>, go soon.".
  offered(feel, how) passes `how` through to openNow.
  anchorDone() is true when the anchor's id is in the visited list. anchorLate() is true when the anchor isn't custom, it's the plan day, and h + WALK > cutoffAt(a, h). anchorOffered(held) = anchorView() && !anchorDone() && (held || !anchorLate()).
  cardStillGood(pending, feel, held): for the anchor it returns anchorOffered(held), otherwise offered(feel, held ? "held" : undefined).
  In renderPlay, restoring a held card passes st.panel === "reveal" as `held`. A card already revealed then survives a reload after Maps until the place actually closes, even when the walk pushes it past the cutoff, and it shows "…Too late now." honestly. Cards held on the commit screen and the commit → reveal step (revealNow) still use the full rule, so nothing is newly revealed past its cutoff.

#30 SEAM: openNow, closingLine, anchorLate and Plan B read the hour only through planHour(). They compare it with v.end and v.last in the catalog's own 24+ frame, where 25 means 1am, and fmtHour(25) already prints "1am". So #30 only has to teach planHour() (and the remaining isPlanDay readers) that 12:30am the next calendar day is hour 24.5 of the plan day.

## Schema changes

Catalog only; the link and the deck don't change.
- PLACES entries, optional `lastEntry`: a number (the same last-entry hour every open day), or an object keyed "0"–"6" like `week` (hours in 24h decimal, past midnight as 24+). The verbatim source sentence must appear in the entry's hoursText.
- PLACES entries, optional `stay`: hours a visit needs before close, as posted by the place ("arrive X before closing"). It replaces the type default. Today only floridarama gets 1.5.
- Legacy STOPS objects: the same optional `lastEntry` (number or weekday map), plus `lastEntryText` (the verbatim quote), since they have no hoursText. Only if research verifies a value.
- Derived, not stored: stopView(id) gains `last` (that day's last entry or null) and `stay` (hours). anchorView() inherits both for a picked dinner; a custom booking has neither, so it's never cut off.
- New constants and functions in index.html: STAY_MIN {museum:60, meal:45, treat:20, other:30}, WALK = 0.25, TIGHT = 0.5, stayFor, lastEntryOn, planHour, cutoffAt, closingLine, anchorDone, anchorLate. Changed signatures: openNow(v, how), offered(feel, how), anchorOffered(held), cardStillGood(pending, feel, held).
- No change to cleanDeck, linkPlan, encodePlan/decodePlan or deck v:1.

## Risks

- Fewer offers late in the day. Museums without a posted last entry now drop at 3:45 for a 5pm close (today 4:30), parks and shops 15 minutes earlier than today, coffee 5 minutes earlier. Late afternoon will show the "That's everything we found open right now" note more often. Mitigation: the list explains each one ("Too late now"), and every number lives in one place (STAY_MIN, WALK, TIGHT) if Jake's play-test says it's too strict.
- Array.filter(openNow) would pass the index as `how`, so listHtml has to use a lambda. The Code Reviewer should grep for any `filter(openNow)` or `.map(openNow)`.
- Float boundaries. h has minute precision, but sums like 14 + 25/60 + 0.25 vs 15 − 1/3 can differ by one ulp at the exact boundary minute. That's harmless in use (one minute). The checks pin times at least 5 minutes off every boundary. If the reviewer wants exactness, compare Math.round(x*60) in cutoffAt and closingLine.
- Classification by cost puts "small"-cost places (Shuffleboard $10 open play, glass-studio demos, TBW) on the 60-minute attraction rule: for example, Friday shuffleboard (7–10pm) is offered until 8:45pm.
- Posted last entry wins (Sunken Gardens until 3:45pm, James until 4:15pm). That's about 30 minutes inside, made explicit with "Last entry …, go soon.". See the PM question.
- Loosening the held-reveal rule means a card already revealed can reappear after a reload past its cutoff, but before close, with "Too late now". That's honest, and it stops a "go soon" card vanishing mid-walk when Maps reloads the tab.
- #30 builds on this branch and must extend planHour() rather than calling nowNY() inside openNow and friends again. Otherwise the two closing rules drift apart.
- Data honesty: only verified quotes become lastEntry or stay values. The Dalí and Morean pages are behind Cloudflare and stay on the default. FloridaRAMA's current hint overstates its source and is corrected here.
- docs/screens/day-rainy-iffy.png and other older shots aren't retaken. None should show the old "Later or closed right now" heading, but QA should glance at them.

## Questions for PM (non-blocking)

The plan builds the recommendation unless the PM says otherwise.

1. **When a place posts its own last entry, should that be the cutoff, or should we also insist on our type buffer and use whichever is stricter? Example: Sunken Gardens sells its last admission at 4pm and closes at 4:30; the James sells until 4:30 and closes at 5.**
   - Option: A. The posted last entry is the cutoff, as the Proposal says. Sunken Gardens is offered until 3:45pm and the James until 4:15pm, and the card says "Last entry 4pm, go soon."
   - Option: B. Whichever is stricter of the last entry and the 60-minute museum buffer. Sunken Gardens is offered until 3:15pm and the James until 3:45pm, and the last entry only shows in copy.
   - Recommendation: A. It follows the ticket's Proposal ("when a place doesn't post one, use a default"), trusts the place's own rule, and the card tells people plainly that time is short, so they choose. If play-testing says 30 minutes inside isn't worth it, it's a one-line switch to Math.min in cutoffAt.
